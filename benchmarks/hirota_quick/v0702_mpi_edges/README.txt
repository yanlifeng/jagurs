V0702 短时 MPI 嵌套边界验证
==========================

目的
----
官方 V0702 把嵌套插值中的非阻塞 MPI 收发缓冲区按边分开，修复同一
进程同时处在两条相对边时复用缓冲区的问题。普通 4×4 MPI 分解一般
不会触发这一条件。本测试特意比较 2×2、1×4、4×1 三种分解。

使用广田湾快速 case 的全部真实地形、三层完整网格、震源输入、2482
个测点和物理参数。只将模拟时长改为 18 秒，并在 9、18 秒输出三层场。
每种分解均为 4 MPI 进程，默认每进程 1 个 OpenMP 线程。

检查内容
--------
以同一个 V0702 修复版可执行文件的 2×2 结果为参考，逐项检查：

* 三层网格、两个输出时刻的全部 eta、qx、qy_south、depth 格点值；
  每种分解共 24 个完整场、7,406,008 个数值，还核对全部坐标元数据。
* 2482 个测点的全部原生 0.1 秒记录，每点 181 个时刻，逐条比较水位
  及两个单宽流量，共 449,242 条时间记录、1,347,726 个物理量数值。
  最后一条 18.1 秒来自当前程序原有的终止时间包含额外一步的约定。
* 记录完整性、时间连续性、有限值及 MPI 正常退出。
* 运行前校验全部冻结输入的 SHA256；不改变输入文件或原黄金参考。

沿用主快速案例的固定容差：水位/海底深度 2e-5 + 1e-6*abs(reference)，
流量 1e-4 + 1e-6*abs(reference)。每个值分别验收，计时不是通过门槛。

运行
----
在仓库根目录，先按照主 README 安装依赖、编译和解包；加载本机 MPI
环境后运行：

  python benchmarks/hirota_quick/run.py prepare
  python benchmarks/hirota_quick/v0702_mpi_edges/run_edges.py

默认程序 build/gnu/jagurs、输入 build/hirota_inputs、输出 runs/mpi_edges。
输出目录必须不存在；可用 --output 指定新目录。
可用 --exe、--work、--mpiexec、--mpi-args、--cores 指定当地环境。
Python 依赖与主案例相同：NumPy、netCDF4。

少进程分解时，沿岸测点可能集中到一个进程，超过 Linux 默认的 1024
个打开文件上限。脚本只在当前进程及子进程中把软限制提升到 8192；若
系统硬限制不足会报错。没有减少测点或修改求解器。

本机复现使用 Intel MPI 2021.12 / GNU 构建：

  source /opt/intel/oneapi/mpi/2021.12/env/vars.sh
  export I_MPI_PIN=1 I_MPI_PIN_PROCESSOR_LIST=96,97,98,99
  export I_MPI_FABRICS=shm:ofi FI_PROVIDER=tcp
  python benchmarks/hirota_quick/v0702_mpi_edges/run_edges.py --cores 96-99

验证范围
--------
这是 CPU、非色散、18 秒真实输入下的 MPI 分解一致性测试，覆盖 V0702
相对边缓冲区所涉及的运行形态。参考是同程序的 2×2 计算，不是独立
物理真值；历史结果回归和独立解析波由主测试另行完成。
这次没有用旧版故障作负向对照，因此不声称已证明旧版在本机必然失败。
本测试没有验证色散、GPU、完整海啸洪峰或 sECOM 精细漫滩。
