## 哪些放在共用代码，哪些放平台目录

| 层次 | 位置 | 本轮内容 / 边界 |
|---|---|---|
| 物理与离散算法 | `src/mod_fxy*`、`mod_hxy*`、`mod_nest` 等 | 方程、时间推进、嵌套和原物理设置不改；不能因平台不同维护两套物理公式 |
| 共用 CPU 工程优化 | `src/mod_onefile`、`mod_displacement`、`mod_newsubs` 等 | MPI 集合汇集、FFT 工作区复用、符合严格格式的震源分块读取；这些不依赖 ARM/x86 指令集 |
| 耦合接口 | `src/mod_coupling_output.f90` | 四个原生场及额外输出时刻；不把具体案例写死到新的计算内核中 |
| 案例和产品选择 | `cases/`、运行的 `tsun.par` | 输出频率、时长、诊断产品、物理开关；不是某种 CPU 专属优化 |
| 平台实现与运行策略 | `platform/lineshine/`、`platform/a4/` | 编译器/依赖库、ISA、NUMA/线程亲和性、MPI 传输、调度器和路径 |
| 验收 | 冻结的 `benchmarks/` + 新 `tests/`、`tools/` | 原输入、参考、容差和验收脚本不改；新脚本只增加测试，不重生成参考值 |

例如：**“少建 FFT plan”是共用优化；“用 MKL 还是 FFTW”是平台选择；“是否输出 vmax”是产品选择。** 不应把所有在 a4 上发现的优化都称为 x86 特化。

## 默认值与推荐配置要分开

| 选项 | 默认 | a4 已选方案 | 注意 |
|---|---:|---:|---|
| `source_field_output` | 1 | 0 | 只去掉逐震源帧的诊断全场，保留震源施加 |
| `legacy_velocity_diagnostics` | 1 | 0 | 关闭历史额外耦合时刻；常规 `itmap` 输出不受影响 |
| `kj_workspace_cache` | 0 | 1 | 复用 CPU FFT plan/缓冲，不缓存源值、水深或滤波系数；GPU 不启用 |
| `source_local_read` | 0 | 1 | 仅接受严格对齐的球面 CF lon/lat 源文件；其他输入保持 0 |
| `error_check_interval` | 1 | 1 | 10/50 已筛查但未推荐；会延迟最多9/49步发现原阈值异常 |
| `--skip-max-velocity` | 不启用 | 启用 | 省掉最大流速图，不省浅水方程更新和最大水位图 |
| native ISA 编译 | 不启用 | 不启用 | a4 筛查收益不足；严格浮点，不用 fast-math |

灵晟初次更新保留旧案例和默认行为，只启用它原来已经验证的 collective gather。**不把 a4 推荐参数一股脑改成所有平台的全局默认值。** 灵晟是否启用新源读取/FFT 缓存，应再用目标输入做配对测试；当前合并并不等于这些可选路径已在 ARM 全部验收。

分块读取是每 rank 的独立 NetCDF 读取，不是集体并行 NetCDF；在超多节点上可能变成文件系统热点，需要另测。缓存已处理网格、分块、通信器及线程数变化，但多种新构建组合仍需测试。原 `USE_GPU` 代码仍在，**本轮不宣称昇腾、曙光 GPU 或 CUDA 后端已经适配/验证**。

## 后续接统一框架的原则

先在这条共享源码线上继续工作，不创建长期漂移的 `arm-src/` 和 `x86-src/`。每项改动分成 `perf(common)` / `platform(...)` / `case(...)` / `test(...)` 类提交，单独回归后再组合。

统一框架可逐步接管动量/水位 stencil、halo交换、场归约、数组分配/生命周期和 FFT 后端；保留现有 Fortran CPU 实现作为可回退参考。先约定数组布局、halo 宽度、精度、设备驻留和同步责任，再替换某个算子，不先大规模搬文件。平台快路径应有显式选择与未支持组合保护，不能偷改物理语义。

每个平台的“可编译、短回归通过、完整事件等价、实测吻合、性能/多节点扩展”分别记录，不合并成一个含糊的“已验证”。所有数值回归都沿用固定输入/观测/容差；NSE 不是任务书的漫滩范围准确率。
